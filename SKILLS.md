# Навыки для работы с проектом «Логистика Analytics»

Клиентский портал складской отчётности (чистый HTML/JS/CSS, без сервера и сборки).

## Технологии
- **HTML5 / CSS3** - рефакторинг разметки портала и сервисов, адаптив, CSS-переменные.
- **JavaScript (ES2020+)** - работа с общими модулями `shared/js/` (`idb.js`, `common.js`), глобальное состояние, события DOM.
- **IndexedDB API** - открытие БД, хранилища, транзакции, `onupgradeneeded`, versioning, `deleteDatabase` (в `idb.js`).
- **Service Worker / PWA** - стратегии кэша (`cache-first`, `network-first`), `caches.match`, `skipWaiting`, `clients.claim`, манифест PWA, сверка версии конфигурации и уведомление о готовом обновлении (`shared/js/pwa-update.js`).
- **SheetJS (XLSX)** - чтение `.xlsx` через `FileReader` + `Uint8Array`, `sheet_to_json`, `cellDates`; защита от занижённого `!ref` (`expandSheetRange`).
- **Chart.js** - создание и уничтожение графиков (`destroyCharts`), адаптивные полотна.
- **ESLint + Prettier + TypeScript-LS** - `jsconfig.json` с `allowJs`, линтинг и форматирование JS/HTML/CSS.
- **Русский язык** - комментарии в коде, документация, общение с пользователем.

## Файлы конфигурации (уже созданы)
- `jsconfig.json` - подсказки и проверка типов для JS через `tsserver`.
- `.eslintrc.json` - правила линтинга.
- `.prettierrc` - единое форматирование.

## Версии и обновления
- Единый источник версий - `shared/js/config.js` (`PORTAL_CONFIG.version`, `PORTAL_CONFIG.services`).
- Главная страница строит карточки сервисов из `shared/js/config.js`; сервисы получают версию
  через атрибут `data-version-service="<id>"` в шапке и подвале.
- Service Worker импортирует `shared/js/config.js` и выводит имя кэша из версии портала;
  при расхождении версий переключает кэш и уведомляет открытые страницы.
- Версия в `package.json` должна совпадать с `PORTAL_CONFIG.version` (проверяется `test/config.test.js`).
- Обновление применяется только по подтверждению пользователя (уведомление «Обновить / Позже»).

## Слияние двух отчётов (сервис «Аномалии склада»)
- Ключ сопоставления артикулов: `Артикул` (отчёт аномалий) ↔ `LM Код` (содержимое ячеек).
- Книга читается локально с `cellDates: false`: в выгрузке есть ячейки-суммы с «дата-форматом»,
  которые при `cellDates: true` превращаются в объект `Date` и теряют значение.
- Числа из выгрузки Power BI приходят в видах `−47`, `103.5`, `1,5`, `431,873.44` - нужен свой разбор.
- Текст в колонке `SSCC` («Всего в 2 паллетах.») - это комментарий, а не паллета: значение переносится в комментарий.
- Итоги по отчётам и структура сервиса покрыты `test/anomalies.test.js`.
- Для анализа аномалий нужны два файла: `not indexed/samples_XLSX/anomalies_Список аномалий запаса.xlsx` и `not indexed/samples_XLSX/anomalies_содержимое ячеек.xlsx`.
- Все примеры XLSX лежат в `not indexed/samples_XLSX/`; папок `Services/*/src/` больше нет. Эта папка используется только тестами и ручной проверкой, в Service Worker не попадает и в git не входит.
- Тесты: 232 всего, 232 проходят, 0 пропущено. Имена файлов канонические, без суффиксов даты. Полный прогон - только локально: CI публикует сайт без тестов, потому что XLSX исключены из репозитория.

## Аналитика логистических операций: КПД и фильтры
- `ANA_WEIGHTS` - единственные веса показателя: `SKU × 2`, `паллета × 1`, `заказ × 1`. Формула КПД не менялась:
  `Σ(операции × вес) / активные 10-минутные слоты`.
- Медианы КПД и справочный ориентир удалены: нет `anaMedian`, `anaKpdMedians`, `anaApplyKpdReference`,
  `ANA_KPD_MEDIAN_*`, карточки «Медиана КПД» и упоминаний в справке, таблице и профиле.
- Фильтр «Должность» (`pos`) добавлен в `ANA_FILTER_FIELDS` и в оба блока фильтров - графиков и таблицы.
  `anaFilterRows` фильтрует по `r.pos`, поиск учитывает должность, `anaFilterOptionValues` сужает список
  должностей под остальные фильтры.
- `ANA_SLOT_FILTER_OPTIONS` = `[0, 5, 10, 20, 30, 50, 100]`, по умолчанию 0 («Все»). Селект живёт в шапке блока
  «🏅 Топ-10» (`anaSlotFilter-<key>`); `anaFilterBySlots` скрывает сотрудников ниже порога только из топ-10,
  но не из графиков и таблицы.
- `anaRankComparator` и `ANA_RANK_SORT_DEFAULT = 'kpd'` задают сортировку топ-10 и таблицы:
  `kpd`, `w` (взвешенные операции), `slots` или `ops`. Клик по заголовку таблицы по-прежнему переопределяет сортировку.
- Графики вкладки «Продуктивность» - круговые диаграммы, а не топ-списки: `anaDoughnutChart` строит кольца
  для операций по категориям, структуры по взвешенным операциям и контекстов операций; в подсказке -
  «значение + доля». Пустые данные показывают `.chart-empty`, а не пустой канвас.
- Отдельных вкладок подразделений и достоверности нет: `ANA_TABS` содержит `rating`, `productivity`, `daily`,
  `hourly`, `shifts`. Подразделения выбираются фильтрами `type` / `dept`; число сотрудников по категориям считают
  карточки статистики из `ANA_CATEGORY_STATS` (внешний персонал по подразделению, остальные - по `cat`). Карточки
  считают уникальные ЛДАП, поэтому один сотрудник может попасть в несколько карточек; общей карточки
  «Сотрудников» нет.
- Отдельным блоком `sec-matrix` ниже таблицы `anaRenderUniversality` строит карту универсальности
  «сотрудник × категория»: считает число категорий на сотрудника, сортирует по нему и красит ячейки через
  `anaHeatColor` по доле операций сотрудника в категории. В ячейке - операции, процент и мини-полоса, справа -
  всего операций, КПД и бейдж «N / 5» с пятисегментным индикатором. Отдельных фильтров нет: `anaSetUniLevel`
  фильтрует карту по числу закрытых категорий (`anaUniLevel`, 0 - все), кнопки-уровни показывают количество
  сотрудников на каждом уровне. Карта не зависит от фильтров таблицы и обновляется из `anaRenderTab`.
- Карточки вкладки «Продуктивность» считают задействованных сотрудников: под числом выводится «задействовано»,
  а над сеткой - пояснение, что один человек может входить в несколько категорий.
- Вкладка «Динамика по часам»: `anaRenderStats` для `kind === 'hours'` берёт три пиковых часа каждой категории
  (сортировка по операциям, при равенстве - по часу) и показывает их в карточках; пустые категории дают «-».
  `anaRenderHourlyCategoryCharts` и `anaRenderHourHeatmaps` пропускают категории без операций и выводят
  `.empty-state`, если данных нет вовсе. Карточки и графики считаются по отфильтрованным строкам `anaChartFilters`.
- Вкладка «День и ночь» (`kind === 'shifts'`): `anaShiftOfSlot` делит 10-минутные слоты на день
  (`450 <= slot < 1170`, 07:30-19:30) и ночь; `anaHydrate` кладёт `shift` в каждую строку. `anaShiftStats`
  считает операции, штуки, взвешенные операции, слоты, уникальных сотрудников, КПД и разрез по категориям для
  каждой смены. `anaRenderShiftCharts` строит три кольцевые диаграммы (`anaDoughnutChart`): операции,
  взвешенные операции и штуки в общем за смену; `anaRenderShiftSummary` - таблицу по категориям; карточки,
  диаграммы и таблица используют один и тот же отфильтрованный набор строк.
- Вкладка «Контекстная продуктивность» (`kind === 'productivity'`, ключ `productivity`) - карточки, топ-10 и собственная
  таблица, без блока графиков (`sec-charts` скрыт). Топ-10 живёт в отдельной секции `sec-top` и сортируется
  через `ANA_PROD_SORT_OPTIONS` (`palletsPerHour`, `skuPerHour`, `piecesPerHour`, `palletOps`, `skuQty`,
  `assemblyOps`, `assembliesPerHour`, `orderOps`, `ordersPerHour`) функцией `anaProdComparator`; ставки `null` всегда в конце.
  `anaRenderProdTopCards` вызывается из `anaRenderProdTopFromFilters` (а не из таблицы), поэтому топ-10 считается
  только по своим фильтрам; первая метрика карточки - выбранная сортировка. Над топ-10 стоит панель
  `anaTopFiltersHtml(tab)` со своим префиксом `tp-${key}-*` (контекст, тип, подразделение, должность, категория,
  операция, сброс) - тот же набор, что над топ-10 вкладки «Продуктивность», но с отдельным состоянием
  `anaTopFilters`. `anaSetTopFilter` пишет в `anaTopFilters`, `anaResetTopFilters` сбрасывает только их,
  `anaRefreshFilterOptions` поддерживает `kind === 'top'` (префикс `tp`). Фильтры таблицы (`anaTableFilters`)
  и топ-10 независимы: изменения в одной панели не трогают другую. В шапке топ-10 есть тот же `anaSlotFilter`,
  что и на вкладке «Продуктивность»: `anaRenderProdTopCards` применяет `anaFilterBySlots`, а `anaSetSlotFilter`
  перерисовывает топ активной вкладки и синхронизирует оба селектора.
  `anaAggEmployees` и `anaTotals` дополнительно считают `palletOps`, `palletSlotSet`/`palletSlots`,
  `palletHours`, `palletsPerHour`, `skuOps`, `skuQty`, `skuSlotSet`/`skuSlots`, `skuHours`, `piecesPerHour`,
  `skuPerHour`, `assemblyOps`, `assemblySlotSet`/`assemblySlots`, `assemblyHours`, `assembliesPerHour`,
  `orderOps`, `orderSlotSet`/`orderSlots`, `orderHours`, `ordersPerHour`, `activeHours`, `avgHoursPerDay`.
  «Сборки» - только операция `ANA_ASSEMBLY_OP = 'Сборка в заказы'`, а не весь
  контекст `order`; её строки идут с контекстом `sku`, поэтому часы сборок входят в SKU-часы. «Заказы» -
  отдельно строки контекста `order`.
  Слоты контекста - уникальные пары «сотрудник + дата + слот»;
  `anaSlotsToHours` переводит их в часы, `anaRate` возвращает `null` при нулевом знаменателе,
  `anaFmtRate` печатает `—`. `ANA_RATE_MIN_SLOTS = 3`: меньше трёх слотов контекста - ставка `null`, а не 0.
  Часы pallet, sku, order и сборок пересекаются и не суммируются; общий знаменатель - только `activeHours`.
  `anaTableColumns('productivity')` задаёт 12 колонок от паллет до активных часов, включая «Сборки»,
  «Сборки/ч», «Заказы» и «Заказы/ч»; часы pallet/SKU и «Ч/день» в таблицу не выводятся. Ставки помечены
  `rate: true`, поля контекста - `emptyOn: 'palletSlots'` / `'skuSlots'` / `'assemblySlots'` / `'orderSlots'`
  (нет контекста - `—`, а не 0), `anaTableCell` печатает ставки через `anaFmtRate`, а `anaRenderTable` ставит
  `null` в конец при любой сортировке.
  Фильтры таблицы свои, экспорт - `anaExportTab`. В карточке сотрудника `profileDayChart` - стек
  столбцов по дням с разбивкой по категориям операций (`stack: 'ops'`, цвета `--cat-*`).
- Списки фильтров строит `anaFilterOptionValues(base, f, field)`: для каждого поля берутся значения строк,
  проходящих все остальные фильтры (само поле не применяется). `type` не зависит от `dept`, чтобы тип можно было
  сменить; чужое подразделение при смене типа и недоступные значения сбрасывает `anaRefreshFilterOptions`.
  Смена операции пересчитывает таблицу по отфильтрованным строкам, выбор категории в фильтре таблицы сбрасывает
  несовместимую операцию.
- Модальное окно профиля блокирует прокрутку через `body.no-scroll { overflow: hidden }` **без**
  `position: fixed`: фиксация body сбрасывала прокрутку к началу страницы. `openAnaProfile` добавляет ширину
  скроллбара к текущему `padding-right` body, `closeAnaProfile` снимает inline-отступ - содержимое не
  дёргается по ширине.
